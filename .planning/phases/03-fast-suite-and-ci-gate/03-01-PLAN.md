  <action>
Per D-01 and D-06, create the recorder as a thin CLI over a pure library.

`scripts/lib/suite-timing.mjs` (no Vitest or fengari import; only `node:` modules) exports small functions, each commented and at most 10 body lines:
- `relFile(root, absPath)`: the path relative to the repo root with forward slashes (for example `scripts/tests/more.test.mjs`).
- `caseKey(assertion)`: `[...ancestorTitles, title].join(" > ")`. This is the same shape as Vitest's `expect.getState().currentTestName`; plan 03-04 relies on that and checks it.
- `fileRows(report, root)`: one row per `testResults` entry: `file`, `tests`, `passed`, `seconds` (`(endTime - startTime) / 1000`), sorted by seconds, longest first.
- `wallSpan(report)`: seconds from the earliest file `startTime` to the latest `endTime`.
- `maxConcurrent(report)`: the largest number of file intervals that overlap at one instant (sweep over sorted start and end points).
- `caseList(report, root)`: every case as `{ file, key, status }`.
- `formatReport(summary)`: the printed text. Header lines in this order, each `label value`: `date`, `cpu` (`os.cpus()[0].model`), `cores` (logical), `node`, `vitest` (read `node_modules/vitest/package.json`), `workers`, `busy before run` (percent), `total wall <N> s` (the process wall time around the Vitest run), `file span <N> s`, `sum of file times <N> s`, `max concurrent files <N>`, `tests <passed> passed, <failed> failed, <skipped> skipped` (skipped is `numPendingTests` plus `numTodoTests`, so a todo case counts as skipped). Then a table of every file (`seconds  tests  file`), all rows, not a top N, since D-01 asks for per-file times.
- `machineBusy(sampleMs)`: busy percent of all cores over a short sample (two `os.cpus()` readings; busy = 1 minus idle delta over total delta). Returns a promise.

`scripts/suite-timing.mjs` (the CLI): parse options with `node:util` `parseArgs` (`allowPositionals: true`): `--workers` (default 2), `--budget` seconds (default 300), `--cases-out <file>`, `--baseline <file>` (task 3 implements it; in this task reject it with a clear message), and positionals passed to Vitest as file filters. Steps: `mkdir` `coverage/`, sample `machineBusy(1000)`, spawn Vitest like `scripts/coverage-lua.mjs` does (same `process.execPath` plus `node_modules/vitest/vitest.mjs`, `cwd: root`, `env: { ...process.env }` so `VG_LOGIN_SCOPE`, `VG_SHUFFLE_SEED` and `LUA_PROFILE` reach the run) with `run --maxWorkers=<workers> --reporter=json --outputFile=coverage/suite-timing.json` plus the filters, time it with `Date.now()`, read the JSON, print `formatReport`. If the JSON is missing, print the Vitest exit status and exit 1. Exit 1 when `numFailedTests` is above 0, when total wall is over the budget (print `over budget: <N> s > <budget> s`), or when max concurrent files is above the worker cap; otherwise exit 0 and print `within budget: <N> s <= <budget> s`.
`--cases-out <file>`: when every case passed, write `caseList` as sorted `file|key` lines (plain `.sort()`, one trailing newline) and print `wrote <N> cases to <file>`; when any case did not pass, write nothing and exit 1.

Add `"timing": "node scripts/suite-timing.mjs"` to `package.json` `scripts`, after `coverage`. No other `package.json` change (D-05 allows no dependency change).
  </action>
