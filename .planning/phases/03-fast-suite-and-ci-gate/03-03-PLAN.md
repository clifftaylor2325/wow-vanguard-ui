<objective>
Build the Lua sampling profiler D-02 puts first in its order and D-06 keeps in scope: `npm run profile -- <area>`, plus a `login` mode that profiles one login on its own.

Decomposition note: tooling only. Task 1 is the tracer: the sampler hooks into the harness's existing count hook and `npm run profile -- login` prints a real attribution end to end. Task 2 widens it to any test area through Vitest and adds the unit tests.

Purpose: tell where a test's time goes (research found 61% of a login's instructions in `wow-stub.lua`, and six modules at 79% of the login's Enable time) so later speed work is measured, not guessed. The profiler changes no test result.
Output: `scripts/lib/lua-profile.mjs`, `scripts/profile-lua.mjs`, `scripts/lua-profile.test.mjs`, a sampler hook in `scripts/lib/lua-harness.mjs`, a dump in `scripts/tests/setup.mjs`, and the `profile` npm script.

- Research prototype (fengari 0.1.5): inside the count hook, `lua.lua_getstack(L, level, ar)` with `ar = new lua.lua_Debug()` and `lua.lua_getinfo(L, to_luastring("Sln"), ar)` give `short_src`, `currentline`, `linedefined`, `name`, `what`; depth 40-60 walks cost about 15% of run time; 4,650 samples over 3 warm logins.

Split into small commented functions.
