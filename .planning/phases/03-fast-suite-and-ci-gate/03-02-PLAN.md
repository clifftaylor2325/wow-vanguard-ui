## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request author -> GitHub Actions | label names, branch names and PR text are attacker-controlled on fork PRs |
| workflow -> repository token | the suite job runs with `contents: read`; only the report job (never on pull requests) may write issues |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-03 | Elevation of Privilege | `full-suite.yml` `if` and concurrency expressions | high | mitigate | Event-controlled values (`github.event.label.name`, `action`, `draft`) are used only inside `if` and `concurrency` expressions, never interpolated into a `run:` script; a new workflow test fails if any `run:` block in the four workflow files holds `${{ github.event` or `${{ inputs.` |
| T-03-04 | Elevation of Privilege | fork pull requests running the full suite | high | mitigate | Trigger stays `pull_request` (no `pull_request_target`, asserted by a test); `permissions` unchanged; the issues-writing `report` job keeps `github.event_name != 'pull_request'` (asserted) |
| T-03-05 | Denial of Service | concurrency group | medium | mitigate | A `labeled` event for any other label gets the `-other-label` group suffix, so it cannot cancel a good run, and the job `if` skips it, so it cannot start a second run on a PR already carrying `full-tests`; pinned by the truth-table test (the hosted cancel behaviour, A2, is unverified until billing clears) |
| T-03-06 | Denial of Service | Actions minutes | medium | mitigate | Drafts never run the full suite and later pushes run it only while the label is on (truth-table cases); the weekly and release runs are unchanged |
| T-03-SC2 | Tampering | npm installs | high | mitigate | No package is added; nothing installed |
