<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| game client -> hooked chat and frame methods | Blizzard calls them for every chat line and frame show, with values that may be secret |
| addon error -> chat | a hook on AddMessage that fails would report into the chat it hooks |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-33 | Denial of service | hot hooks: `ChatExtras` and `GameAlerts` AddMessage, `DataBars` Show and SetShown | medium | accept | one wrapper call and an `xpcall` per firing (research A4); measure with `/vg perf` in game |
| T-02-21 | Denial of service | a failing `AddMessage` hook reporting into chat | medium | mitigate | `ns.Report` prints a text once per session, de-duplicates by text, and the `forwarding` flag stops a handler loop (Events.lua); the guard adds no printing of its own |
| T-02-34 | Information disclosure | chat-line values in error text | medium | mitigate | `errorText()` names a hidden (secret) error value instead of reading it; no site builds a message from the hooked arguments |
| T-02-SC | Tampering | npm installs | low | accept | no package is added |
</threat_model>
