How to mark a deliberate error (D-01; the API from plan 02-01):
- Import `expectErrors` (and `AURA_FALLBACK` when needed) from `./helpers.mjs`. Inside the case, call `expectErrors(<matcher>, ...)` with one matcher per distinct entry the case causes on purpose.
- A matcher is the whole entry text as a string (`"DB upgrade 4: eval:2: boom"`). Use a RegExp only where a file line number or a generated counter varies (`/^TEST-ONLY: \d+$/` for the 20-entry cap case), and then anchor it with `^` and `$` and let it vary only in digit runs (`\d+`), escaping every other symbol. `expectErrors` enforces this (plan 02-01): it throws a TypeError naming D-01 for an unanchored, empty or wildcard pattern, a character class, a group, an alternation, `\w`/`\s`, a `g`/`m`/`y` flag, or an empty string, so such a marker fails its case at once.
- A case that clears the list with `ns.ClearErrors()` or `/vg errors clear` still has the cleared entries judged (the harvest), so name them too.
- Every matcher must match an entry, or the case fails as "expected but never seen".

D-04 stop rule: an "unexpected error" is an entry the case does not cause on purpose. Count them by root cause. R1, R2 and R5 below are already known. Record every root cause met, known or new, with its texts and cases, in the SUMMARY under `## D-04 tally`. STOP and return `## CHECKPOINT REACHED` with that list, before committing more, if:
- this plan meets more than 5 root causes not in the known list; or
- one fix would change more than about 20 lines of addon code (Core/ or Modules/), touch a second addon file, or change what a player sees.
The user decides. Do not choose a fix or a marker for them, and commit nothing further until they answer.
