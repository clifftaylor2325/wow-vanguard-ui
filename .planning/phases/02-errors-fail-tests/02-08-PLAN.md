<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| player click (hardware event) -> addon OnClick -> restricted auction call | Post, buy and cancel must run inside the click's hardware event |
| game client -> hooked auction frame methods | Blizzard calls the hooked methods with its own values |
| addon error -> chat, `/vg errors`, the game's handler | error text leaves the addon |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-16 | Elevation of privilege | `W.Button` / `W.Primary` OnClick -> `C_AuctionHouse.PostItem`, `PostCommodity`, buy and cancel | high | mitigate | the guard runs the handler synchronously in the same call stack (`ns.Try` `xpcall`); no click work moves to a timer; the stub's hardware counter (`clicked = stub.hardware > 0`) still logs `true` in `auction.test.mjs`; the real client is on the in-game list (A1) |
| T-02-01 | Information disclosure | auction error text through `ns.Guard` -> `ns.Try` | medium | mitigate | same control as plan 02-01: `errorText()` names a hidden error instead of reading it; no site builds its own message |
| T-02-17 | Tampering | factory labels built from button text | low | accept | labels come from the addon's own button captions, built once at creation; no game-supplied value goes into a label |
| T-02-SC | Tampering | npm installs | low | accept | no package is added |
