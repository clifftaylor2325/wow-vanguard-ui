# Vanguard theme spec ("Slate & Brass")

This is the reference every style change cites. It is written from `Core/Theme.lua` (and `Core/SharedMedia.lua`, `scripts/lib/media-sources.mjs`) as they are, not from the work plan's notes: where the two disagree, the code is what ships and this page follows the code (see [Where the plan and the code differ](#where-the-plan-and-the-code-differ)). If you change a token, a role or a primitive, change this page in the same commit.

The look in one line: flat dark slate panels, one-screen-pixel borders, one accent colour, one font (Fira Sans Condensed), and textures that are plain white or grayscale shapes tinted by the theme. Nothing depends on art from another addon.

## Rules

- **Colours and font sizes live only in `Core/Theme.lua`.** Modules ask for a colour by token name (`T.RGB`, `T.Color`, `T.Tint`, `T.BarColor`, `T.Paint`, `T.Hex`) and for text by role (`T.Text(fs, role)`). `scripts/lib/code-quality.mjs` fails the build on a colour setter called with numbers, a 0-1 colour table, a written-out `|cff......` escape, or a `:SetFont(path, <number>)` outside the theme.
- **Every painted frame follows live changes.** `T.Panel`, `T.Button`, `T.EditBox`, `T.CloseButton` and `T.Crest` remember what they painted; `T.Refresh()` (run by `/vg accent`, the accent swatches, a font or text-size change, a UI scale change) repaints them, re-fonts every string styled with a role, recolours every string coloured by token and re-tints every region tinted by token. Anything coloured by hand registers with `T.OnChanged(fn)`.
- **Primitives are idempotent.** Calling one again on the same frame repaints it; it never adds a second border.
- **Other addons get the same tools** through the Skin API (`Vanguard.RegisterSkin`, `Core/Skin.lua`): `S.Panel`, `S.Button`, `S.EditBox`, `S.CloseButton`, `S.WindowControl`, `S.FadeRegions`, `S.SetFont`, `S.Text`, `S.Color`, `S.RGB`, `S.Tint`, `S.BarColor`, `S.Pixel`, `S.Accent`, `S.PanelColor`, `S.Font`, `S.OnChanged`, and the game frame primitives below (`S.Tab`, `S.CheckBox`, `S.Radio`, `S.Divider`, `S.ArrowButton`, `S.Slider`, `S.Tooltip`, `S.ScrollBar`, `S.FontObjects`).

## Colour tokens

`T.RGB(name)` returns r, g, b, a (0-1). Four tokens come from the theme settings, so a profile can change them; the rest are fixed. A name that is not a token is an error, not a silent white.

`T.Tint(region, token, alpha)` colours a texture (vertex colour) by token and remembers the token, the alpha and the colour it set, in a weak table. `T.Refresh` re-tints every remembered region whose vertex colour is still the one `T.Tint` set (within a 255th on each channel), so icons, arrows, rails and washes follow an accent or variant switch the way `T.Color`'s text does; a region recoloured by hand since (a class colour, say) is forgotten and left alone. A region that cannot give its colour back is forgotten at the first refresh too.

| orchid | `b48ae8` | void, purple |

The state colours (`good`, `warn`, `bad`) are kept apart from every preset, so an accent never reads as a warning, and jade, orchid and copper keep clear of item quality and class colours too (#231: they replaced fel `5bcb7e`, near Uncommon and Hunter; void `a47bf0`, near Epic and Warlock; and ember `e0664b`, near `bad`). ## Text

### Fonts

| Setting `font` | Font |
| --- | --- |
| `""` (default) | Fira Sans Condensed, bundled: Medium for regular roles, SemiBold for bold ones (`T.FONTS.regular`, `T.FONTS.bold`). Latin, Greek and Cyrillic, tabular digits. |
| `"client"` | The game's font (`STANDARD_TEXT_FONT`). Korean and Chinese clients always use it, whatever the setting. |
| any other name | A font shared through LibSharedMedia. The Font picker lists only Vanguard's two fonts, plus this one while it is the font in use (from a profile or an older setting); other shared fonts are not offered. If the addon that shared it is gone, Fira Sans Condensed comes back. A font path from older settings still works. |

Vanguard shares its own fonts through LibSharedMedia as "Vanguard Fira Sans" and "Vanguard Fira Sans SemiBold" (western and Russian clients). The faction look swaps the font of the `title` and `heading` roles only (`T.HEADING_ROLES`, the two display roles, used only for window and card titles): Cinzel SemiBold for Alliance, Metamorphous for Horde, and only while the faction look is `"auto"` (Crest and heading font; the default `"crest"` keeps the usual fonts), the Font setting is Fira Sans and the client uses it (not on Russian clients: Cinzel and Metamorphous have no Cyrillic). Every other role, `zone` among them, keeps Fira Sans whatever the look. The font and text size apply at once (every role-styled string is re-fonted).

### Text roles

`T.Text(fs, role, color)` sets the font, size, shadow or outline, and a colour token (`text` unless given; `false` keeps the colour). Sizes are at Text size 100 %; the Text size slider (General → Look, 70 % to 130 % in steps of 5 %, also set by the setup wizard's screen presets) multiplies them, rounded to whole points (`T.ScaledSize`). Roles without an outline get a 1 px drop shadow in `textShadow`; outlined roles get no shadow. `T.TextSize(fs, size)` draws a styled string at a size of its own, worked out from the roles' sizes (`T.RoleSize`), and keeps it when text is refreshed (raid tile deficits follow the tile's scale this way, never below `tiny`).

`T.FitText(fs, box, inset)` fits a label on one line across a frame, `inset` in from each side (`T.SPACE.gap` unless given): while its text is wider than that (a translation, Larger text), it shrinks, down to `T.FIT_FLOOR` (84 %, a 12-point label to 10), and only past that does the client cut it short with an ellipsis. It fits again after every new text, a resize of the frame and a text size change. Every dialog button's label (`ns.DialogButton`, so `W.Button`, `W.Primary` and `W.KeyCapture`) is fitted this way. A button with room beside it grows to its label instead (`ns.WidenToLabel(b)`: the label's full width and `T.SPACE.gap` either side, never narrower): Train all on the trainer, the profile rows' buttons and the raid tools' call buttons, which share the widest one's width. A line of game data that can run any length (a spell, a merchant, a destination) keeps to its room on one line and is cut short there: `ns.SingleLine(fs)` for a string anchored on both sides already, `ns.EndAt(fs, frame, right)` to end it `right` in from a frame's right edge (`Core/Chrome.lua`). `scripts/tests/textfit.test.mjs` is the check that text fits (see [DEVELOPMENT.md](DEVELOPMENT.md)).

## Spacing

`T.SPACE` holds the only spacing numbers for new and restyled layouts, in UI units, on a 4-unit scale:

| Token | Units | Where |
| --- | --- | --- |
| `T.SPACE.section` | 24 | The gap between one section and the next. |
| `T.SPACE.pad` | 16 | The inset of a floating window's or dialog's contents from its panel edge. |
| `T.SPACE.col` | 12 | The gutter between columns, and a card's or panel's inset inside a window (the options cards). |
| `T.SPACE.gap` | 8 | A HUD card's inset (the meter, instance prep, mail tools, crafting, group threat, rolls, the officer roster) and the gap between controls. |
| `T.SPACE.tight` | 4 | The gap between cells. |

The rest of the scale:

- **2 px** only for the gap between repeated cells of one control (minimap buttons, swing timer rows, the raid tools buttons, action buttons). Raid tiles are the exception: they sit 4 apart by default (`RF.defaults.spacing`), and the player can change it.
- **Heights** are named too: `T.ROW.height` (28) for a list row and the options window's check, cycle and slider rows; `T.CONTROL_H` (20) for an inline control (a dropdown, an input, a segment group, a switch's track, a menu item); `T.BUTTON_H` (26) for a standalone button; a text line is 20.
- **Window chrome** sits on `T.CONTROL`: a window title at (`T.SPACE.pad`, -`T.CONTROL.inset`) from the panel's top-left corner, on the close button's line; a card title at (`T.SPACE.gap`, -`T.SPACE.gap`).
- **One capsule** (`T.Capsule(frame, height, tier, opts)`): a pill of any height, its fill in the token `tier` (`inset` for a track) over three slices (round ends `height / 2` wide, a flat middle) and a one-pixel outline in `borderHi` over it (`opts.line` another token or `false` for none, `opts.edge` `SliderLine` for the 8 unit slider track, `opts.layer` the fill's layer). It returns `{ fill, line }`, the parts a caller retints. The switch track, the slider track and the error badge (14 high, `accent`, `void` count, `99+` at most) are capsules; the slider's fill uses `T.CapsuleArt`. The `PillLine` outline is 2 texels of 32, about one screen pixel at 18, 14 and 12 high (a media test keeps it so).
- **One scroll thumb** (`T.SCROLL`): `thumb` (4) units wide, in `text2` at `rest` (0.5) alpha and at `lit` (1) while the mouse is over it or it is dragged, with no arrows; `ns.ScrollView` (the options pages, What's new, the quest log and quest dialog, the dialogs' lists and text areas) and `T.ScrollBar` (the game's own bars) both draw it so.
- **Widths and dialogs.** A button is 120 wide unless its row needs another. Every dialog shares `ns.DIALOG` (`Core/Dialog.lua`): `head` (40, the title line's `T.CONTROL.inset` and a `T.SPACE.pad`) is where its contents start, `foot` (50, a `T.SPACE.pad`, a `T.BUTTON_H` button and a `T.SPACE.gap`) the room along its bottom; its buttons sit at (-`T.SPACE.pad`, `T.SPACE.pad`) from the bottom-right corner with `T.SPACE.gap` between them.
- Borders and sheens are measured in screen pixels, not UI units (below), so they never count toward the grid.
- A number that is none of these stays a local constant with a comment saying what it is (the options window's `WIDTH, HEIGHT, NAV_WIDTH = 780, 600, 176`, say). The code-quality scan fails a padding, gap, margin or inset constant set to a written number off the scale (0, 1, 2, 4, 8, 12, 16, 24); HUD placement (`Core/Layout.lua`, bag slots, the minimap zone text, nameplate hit boxes) is exempt.

## Panels, borders, sheen, shadow, glow

| Primitive | What it paints |
| --- | --- |
| `T.Panel(frame, opts)` | A `panel` fill (`inset` with `opts.inset`, `raised` with `opts.raised`, alpha `opts.alpha`), a one-screen-pixel border in `edge` (or the accent with `opts.accent`, or `T.SetBorder`'s colour), a one-pixel `sheen` line just inside the top border, and with `opts.shadow` a soft shadow. A raised panel (or `opts.bevel`; `T.Button` always) also gets an inner bevel (#234, `T.BEVEL`): a one-pixel `borderHi` line at 35 % on the first row inside the top border and a `shade` line at 35 % on the first row inside the bottom, and its sheen moves down to the second row so the two never merge; `opts.noBevel` leaves it out (slots have their own). `opts.pad` draws it all that many units out past the frame (game windows use 6, room their thick border art used to take; `T.Padding(frame)` reads it back). `noBg`, `noBorder`, `noSheen` leave a part out; `noSurface` keeps the panel texture off (the HUD). With `panelGradient` on (`/vg gradient`, off by default, #259) a floating window's fill (`opts.shadow`, or `opts.gradient`) runs from `T.PANEL_GRADIENT[1]` (-0.012) to `[2]` (+0.012) OKLCH lightness bottom to top (`SetGradient` VERTICAL, alpha kept), about 2.4 % in all, under 7 of 255 levels; smaller panels stay flat. |
| `T.HudPanel(frame, opts)` | `T.Panel` for the HUD (unit frames, bars, the minimap): never a sheen, and a shadow only when "Soft shadows under frames" (`hudShadow`, off by default, applies on reload) is on, so the screen stays calm. |
| `T.Button(button, kind)` | An `inset` panel, the template's art faded out, and an eased hover (#257): a `raisedHover` fill (a `T.FillParts` fill, so it follows rounded corners) over the inset and a one-pixel `borderHi` line inside the top border, easing in over `T.HOVER_IN` (0.1 s) and out over `T.HOVER_OUT` (0.13 s), eased out (`OUT` smoothing), every texture of the fill at once, never on a disabled button, cleared at once when the button hides or shows (`T.EaseHover`); the hover comes on only while the mouse is really over the button (`T.MouseIsOver`), since the game can call `OnEnter` itself. **Borders are one screen pixel at any UI scale.** `T.Pixel(frame)` is the length of one physical pixel in the frame's units (the client's `PixelUtil` factor, else 768 / screen height, over the frame's effective scale). It is never rounded to whole UI units, which would give 2 px at 1440p and 3 px at 4K. Textures painted by the theme are kept off the client's pixel-grid snapping (`T.Snap`) so 1 px lines stay crisp. `T.Snap(texture, class)` puts a texture under one snapping policy by class (`T.SNAP_CLASSES`): with texel snapping on (`/vg texelsnap`, off by default until an in-game A/B test settles it, #226) the still classes (`border`, `fill`, `divider`, `sheen`) snap to the pixel grid with a bias of `T.SNAP_BIAS` (1), and the moving ones (`bar`, `spark`, `swipe`) and art (`icon`, the default) stay off. `T.SetTexelSnap(on)` and `T.Refresh` re-apply it to every texture at once. A status bar's border is drawn on its top layer (the fill would cover a lower one). "Pixel-perfect scale" (off by default) sets UIParent to 768 / screen height times `pixelMultiple` (a whole number, 1 unless setup's Pixel-perfect preset picks 2 for a 4K screen), out of combat, so one UI unit is one or two whole pixels; the setup wizard's other screen presets turn it off, since they set the game's UI scale instead.

**Sizes and offsets land on whole screen pixels.** `T.PixelRound(frame, length, even)` rounds a length to whole pixels at the frame's scale (to an even count with `even`, for things centred on a frame). `T.PixelSize(frame, w, h, even)` sizes a frame that way and remembers it; panel padding, glows and sheens, the close and window controls, arrows, the logo, unit frames, the options and setup windows and the action bars' button sizes and gaps use them. When the UI scale, the screen size or a frame's mover scale changes, `T.Rescale()` sizes them again on the next frame, out of combat (queued until the fight ends), and calls the `T.OnScale(fn)` listeners (the action bars lay out again).

**Shadows** are a nine-slice ring of `Media/Textures/Shadow` (black, 0.8 alpha, soft falloff) reaching 10 units around the frame on every side, rounded to whole pixels, on the BACKGROUND layer. Floating windows always have one: the options window, setup, dialogs, menus and popovers, the quest dialog and log, tooltips, bags, skinned game windows, alerts. HUD frames have one only with `hudShadow`. With `sliceRings` on (`/vg nineslice`, then a reload; off by default until an in-game check, #236) each shadow and glow is instead one texture the client slices itself (`SetTextureSliceMargins`, `T.SLICE_MARGIN` 16 texture pixels, the client's default stretched mode), anchored the same whole-pixel distance out; a client without texture slicing keeps the eight pieces.

## Materials and states

**One material per window.** Inside a panel every inner surface is one of three tiers, by what it does, and art stays only where it is the content (a portrait, an icon, a talent tree's spell icons, the map, a letter's attachments). A skinned window shows no parchment, painted backdrop, bronze frame, wooden plate or gold rim inside it: what the game drew is faded by alpha (`T.FadeRegions`, `GW.FadeParts`) and a tier is painted behind the part. The window files share their skin helpers in `Modules/Windows.lua`: `GW.SkinTitle` (a title), `GW.SkinGlyph` (a button whose picture is its normal and disabled texture), `GW.SkinDropdown` (a flat button that keeps its arrow), `GW.SkinSearch` (an edit box that keeps its magnifier) and `GW.DressChecks` (a window's check buttons as `T.CheckBox`). `GW.WatchRows(box, skin)` dresses the rows of a game scroll box (the rows it has now and each one it makes or recycles later) once per box, and `GW.SCROLL_KEYS` names the scroll bar keys a window's bars are found under. What a window adds inside its frame is registered in `GW.INSIDES` by the window's name (`GW.SkinFramed` runs it after the window skin), built from `GW.InsetPanel` (a game well faded and painted as an inset), `GW.SkinItem` (the bags' item look on an item button), `GW.SkinMoneyInput` (a money input line's three boxes as edit boxes, their coins kept; the auction house's large lines give their keys and coin key) `GW.SkinMoneyDisplay` (a `MoneyDisplayFrameTemplate` line, the auction house's: the three figures in the number role, the game's colour and icons kept, followed when the game sets its own font) `GW.SkinCoinBox` (a money line in a gold coin box: the box a flat inset, the figures in the theme font) `GW.TextNamed` (named font strings in a role and a theme colour), `GW.TextRegions` (a frame's unnamed labels, found by the game string they show), `GW.SkinEditBox`, `GW.SkinRadio`, `GW.SkinButton`, `GW.SkinPlate` (a button that keeps its icon on a control tile), `GW.SkinProgress` (a status bar as a flat inset track), `GW.FadeArt` (a frame's own art faded), `GW.SkinPictureSlot` (an item button whose picture is its normal texture, the mail attachments), `GW.SkinPager` (a paging arrow with a caption), `GW.Part` (a part by a dotted path of parentKeys), `GW.EachKey` (a skin run on each key of a frame) and `GW.EachPart` (on each dotted path), `GW.KeepKeys` (parts to keep when a frame's art is faded), `GW.SkinText` (a font string in a role and colour), `GW.SkinArrow` and `GW.SkinPaging` (a pager's arrows and count), `GW.SkinIconDropdown` (a dropdown whose picture is an Icon) and `GW.SkinArrowDropdown` (one whose Icon is the game's yellow arrow box, swapped for the theme arrow), `GW.SkinSection` (a section head: the `section` role in `text2`, upper-cased once), `GW.SkinSchematicForm` (the professions recipe form, shared by the crafting page and the inspect window), `GW.FadeFrame` (a nine-slice frame faded by its alpha) and `GW.HookAfter` (a hook on a game method, once per frame and method). Depth is said by the fill, the one-pixel `edge` border, the sheen, the bevel on raised things and one soft shadow under floating things; never by a second border, a glow or a bigger shadow. A switch's press drops its knob one pixel and changes no colour. The dropdown menu closes on Escape, on a click outside it (a catcher frame under the menu) or on a pick, and shows the 4 px scroll thumb (`T.SCROLL`) beyond 16 rows. No fade or sound is added by this.

The controls with a moving part (the switch's knob, the slider's thumb) keep this vocabulary on their own geometry. One exception stands: a slot's accent edge brightens under the mouse (`T.SLOT_STATES`), which stays: on an action button the accent edge is the slot's border.

## Icons

`Media/Textures/Icon.tga`, the icon the game's addons list shows (`## IconTexture` in the TOC), is the one pre-coloured image: Vanguard's crest, two swords crossed behind a rimmed brass shield that bears a serif V, drawn at 64 x 64 px by `scripts/lib/media-brand.mjs` from the same 1024-unit drawing as the website's logo (`art/brand/vanguard-crest.svg`, the reference). The rivets, the fullers, the grips' wrap and the V's engraved line are left out at that size.

`Media/Icons/*.tga` are white glyphs made at 32 x 32 px by `scripts/lib/media-sources.mjs`. Most are line glyphs drawn on a 16-unit grid and shown at 16 px (menu strip, close and arrow controls, the chat bar's `Search` and `Copy` tiles) or smaller (raid marks at about 10 px, which are filled shapes for that reason). The options nav's page icons (`Nav*`) and the minimap's two slot buttons (`Minimap*`) are filled silhouettes rasterized from game-icons.net SVGs (`SILHOUETTES`; CC BY 3.0, credited in `art/CREDITS.md` and `Media/Icons/CREDITS.txt`) with one unit of clear air around them, shown at 16 and 12 px. The stroke rules below are for the drawn line glyphs; the tinting rules apply to all. Every tinted image is white in every pixel, its clear ones included, with the shape only in alpha, so filtering never pulls a dark fringe into a tinted edge; icons and the stand-alone shapes (the diamond, the unit frames' classification diamond `LogoLeft`, the crest) keep at least one clear pixel inside their canvas edge (`scripts/media.test.mjs` checks both). `QuestBang` and `QuestQuery`, an exclamation mark and a question mark at 16 px, are the marks on the quest dialog's and quest log's lines: tinted `gold` for a quest you can take (the bang) and for one ready to turn in (the query), `muted` for one in progress (the query again); the world map's quest-start pins show the bang untinted. The minimap's quest spots show the `Knob` dot at 8 px in `accent` for objectives and the query at 12 px in `gold` for a turn-in, drawn over the dots; the quest the arrow follows gets its mark 4 px larger.

- **One grid unit is one pixel at 16 px.** Strokes are 2 units (2 px) wide (`STROKE`).
- **Straight strokes sit on whole units** (`crisp`, `rect`: square-ended boxes), so each covers exactly two rows or columns of pixels at 16 px instead of smearing across three. `scripts/media.test.mjs` checks that the icons made only of straight strokes have no half-covered pixel at 16 px.
- **45-degree strokes run half a unit off the grid** (the close cross, the check, the arrows, the map diamond), which lands each step of the stroke on whole pixels.
- Where 2 px strokes do not fit, a glyph uses filled shapes (the raid marks); curves (rings, arcs) stay round. They are tinted with tokens: `text2` at rest in the options nav, `text` at rest on the menu strip, the accent under the mouse or when selected, `disabled` when disabled. Regenerate them with `npm run media`, never by hand; `node scripts/build-media.mjs --check` (and `npm run verify`) fails if a committed file does not match its source, or no source makes it any more (`npm run media` deletes those).

Game icons (spells, items, auras) go through `T.Crop(texture, w, h)`: it trims `T.ICON_EDGE` (0.08) off every edge, the art's baked-in bevel, and given a slot that isn't square, crops the long axis further so the icon keeps its aspect ratio (#259). Every slot Vanguard draws today is square.

## Motion and sound

Vanguard moves little and quietly. Every fade goes through the theme (`T.FadeIn`, `T.FadeOut`, `T.StopFade`, `T.OpenWindow`, `T.CloseWindow`, `T.EaseHover`): an alpha animation, eased out, on frames that are not protected (never a secure frame) or on a button's own textures, 0.12 s unless the caller asks for another length. A window opens with `T.OpenWindow` (#257): it fades in over `T.WINDOW_OPEN` (0.13 s) while rising `T.WINDOW_RISE` (4) screen pixels into its own spot, so it ends on the pixel grid, and opens at once in combat; `T.CloseWindow` fades it out over `T.WINDOW_CLOSE` (0.1 s). **In combat no fade lasts longer than 0.15 s** (`T.COMBAT_FADE`, applied by `T.FadeTime`): combat counts from the fight's `PLAYER_REGEN_DISABLED` (which comes just before the client's lockdown) until `PLAYER_REGEN_ENABLED`. **Reduce motion** (General → Motion and sound, off by default) turns every fade into an instant show or hide. **Interface sounds** (on by default) turns Vanguard's own interface sounds off. Everything else that changes on screen does so at once, without animation.

The game's own sounds (error messages, the micro menu, windows Vanguard restyles) stay the game's.

## Where the plan and the code differ

The work plan (P4.1) described the theme from an earlier review. The code is what ships, so this page follows it:

- **Text sizes.** The plan says "title 14 … tiny 9". The code has `title` 15, `heading` 13, `name`, `label` and `number` 12, `cell` 11, `small` and `tiny` 10, `badge` 9 (the only role under 10, #258), plus the outlined roles (`world`, `barName`, `barSmall`, `cooldown`, `auraCount`, `auraTimer`, `auraTimerSmall`) and `chat`.
- **Spacing grid.** The plan speaks of a 4/8 px grid. The code has `T.SPACE` (4, 8, 12, 16, 24) for new and restyled layouts; older layouts still use mostly even offsets (2 to 16) of their own until they are restyled.
- **Bar textures.** The plan names "bar textures" generally. The code has three built-ins (Vanguard, Soft, Flat) and, since P3.5, every bar texture shared through LibSharedMedia; it also shares its own bars and fonts under the "Vanguard ..." names.
- **Fonts.** Besides Fira Sans Condensed and the game's font, a font another addon shares through LibSharedMedia still works when a profile names it (the Font picker shows it only while it is in use; P3.5 listed every shared font), and the faction look adds Cinzel and Metamorphous for titles and headings.
- **Accents.** The plan's five presets were brass, arcane, fel, void and ember; the code now has brass, arcane, jade, orchid and copper (#231) and also accepts any hex colour and the older names fel, void, ember, bronze, blue, green, purple and red.
- **Default sizes** of unit frames, raid tiles, action buttons, the menu strip and windows are not theme tokens; they live in each module and the setup wizard's screen presets (`Core/Setup.lua`), and are described in the feature pages (`docs/features/`).
