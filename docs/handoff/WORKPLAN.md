## 0. How to work (read this first, follow it exactly)

1. **Order.** Do the phases in order (P0 → P4) and the tasks within a phase in order, unless a task says it is independent. Do not start P3/P4 while a P0 task is open.
2. **One task = one commit.** Branch per phase: `work/p0-hardening`, `work/p1-performance`, `work/p2-defects`, `work/p3-features`, `work/p4-style`. Open one PR per phase (CI only runs on pull requests, `.github/workflows/verify.yml`). Commit subject: `P1.3 RaidHealing: cache watched buff names`; body: what changed, what was verified, anything left for in-game testing.
3. **Before each task:** read every file the task names, in full, plus `README.md` for the feature's intended behaviour. The README is the spec; if your change alters behaviour the README describes, update the README sentence in the same commit.
4. **After each task, all of these must pass:** `npm run verify` (tests + the code-quality scan), `npm run coverage` (floor is 100 % of lines, `scripts/lua-coverage-floor.json`, so every new line needs a test that executes it), `npm run lint` if `luacheck` is installed, and `node scripts/build-media.mjs --check` if you touched `Media/` or `scripts/lib/media-sources.mjs`. Tick the task's checkbox in this file in the same commit.
5. **Repository rules the CI enforces** (`scripts/lib/code-quality.mjs`): every function has a comment on the line directly above it; a function body is at most 10 lines of code (nested functions count toward the parent); no colour literals or font sizes outside `Core/Theme.lua` (use `T.RGB`, `T.Color`, `T.Text`, theme tokens); luacheck's `read_globals` in `.luacheckrc` must list every WoW global you start using; `scripts/lib/wow-widget-api.lua` must list every widget method you call (a method not listed is `nil` in tests, on purpose). Add a name there only when you have confirmed it exists in the 12.1 client (Blizzard's `wow-ui-source` or the API docs), never to make a test pass.
6. **Addon rules the game enforces:** never call a protected function or touch a secure frame's attributes/anchors in combat; route such work through `ns.OutOfCombat(fn)` (`Core/Combat.lua`). Never read, compare or do arithmetic on a value that may be secret; use `ns.IsSecret`, `ns.PlainNumber`, `ns.AurasSecret` and pass secrets straight into widget setters. Prefer `C_Item`/`C_Spell`/`C_UnitAuras` over the removed globals (`GetItemInfo`, `GetSpellInfo`). Identify the Forever client by TOC interface version (`ns.IsForever`), not `WOW_PROJECT_ID` (it reports 1 on Forever beta).
7. **Nothing here has been run in the game.** The tests run the real Lua under a stub (`scripts/lib/wow-stub.lua`) that cannot model taint, combat protection, real rendering, Blizzard frame internals or event timing. A task tagged **[VERIFY IN GAME]** needs the owner to test it in the Forever beta/client; implement it, add stub tests, and list it in the PR description under "needs in-game check". Do not claim it works in game.
8. **Stop and ask** only when a task is tagged **[DECIDE]** and the decision changes the implementation. Otherwise make the smallest reasonable choice and say so in the commit body.
9. **Environment note.** If `npm ci` fails with HTTP 403 `host_not_allowed`, the sandbox's network egress is blocking `registry.npmjs.org`; tell the owner, do not work around it.

### Writing a test (the harness in two minutes)

- Tests live in `scripts/tests/<area>.test.mjs` since the headless test client landed (2026-10-03; one file per area, shared helpers and ENV strings in `scripts/tests/helpers.mjs`, the scenario API in `scripts/tests/README.md`). Before that they were one file, `scripts/verify-lua.test.mjs`, which older task text below still names: read it as the area file for that module. The harness is `scripts/lib/lua-harness.mjs`: `createAddon()` loads the stub and the real addon in fengari; `loggedIn(extraLua, opts)` gives a logged-in addon; `addon.eval("return ...")` runs Lua with `ns` in scope and returns the first result; `addon.fire(event, ...)` dispatches an event; `setCombat(addon, true|false)` toggles combat (leaving it fires `PLAYER_REGEN_ENABLED`); `addon.chat()` returns printed chat lines.
- The stub has no `C_*` namespaces or Blizzard frames: each test defines the globals the code under test reads, in a Lua string (see `RAID_ENV`, `UNITS_ENV`, `QUEST_ENV` in the test file) passed to `loggedIn(...)`. Widget state is recorded, so `frame:GetAlpha()`, `GetPoint()`, `GetText()`, `IsShown()` return what the addon set.
- Secrets are tables `{ __secret = true }` and the ENV defines `issecretvalue`; use them to test the secret-safe branches.
- Assertions: prefer `expect(actual).toBe(expected)` over `expect(cond, msg).toBeTruthy()` so a failure shows values.
- A new branch that only runs in game (e.g. the real `PixelUtil`) still needs a stub test that defines the global and exercises the branch, or coverage drops below the floor.

## 1. Facts about the project you need

- ForeverUI is a from-scratch full UI suite for **WoW Forever** (Blizzard's 12.1 engine with vanilla content; TOC `## Interface: 16001, 120007`). Forever's beta runs until Oct 21, 2026; launch is Nov 4, 2026. Forever uses the Midnight-era addon rules: combat values (health, auras, some chat) are "secret" in instanced combat; addons may display them, not read them.
- 68 Lua files: `Core/` (24 files, 5,371 lines: events, DB/profiles, theme/skin, movers, options, setup) and `Modules/` (44 files, 8,692 lines). Load order is the TOC.
- Key internal APIs: `ns.Module(name, def)` registers a module (`def.Enable(settings)`, `def.defaults`); `ns.On(event, fn)` / `ns.Off` is the shared event bus (no unit filtering yet); `ns.OutOfCombat(fn)` queues work until `PLAYER_REGEN_ENABLED`; `ns.Try(where, fn, ...)` is a logging pcall feeding `/fui errors`; `ns.Settings(key, defaults)` returns the active profile's table for a module; `T.*` in `Core/Theme.lua` is the theme (`T.RGB`, `T.Panel`, `T.Text`, `T.SetBorder`, `T.Pixel`, `T.Refresh`); `A.*` in `Core/Auras.lua` builds aura containers on either the client's `AuraContainer` engine (`Core/AuraEngine.lua`) or a legacy icon backend (`Core/AuraLegacy.lua`); `ns.Mover(frame, key, label, default)` makes a frame movable; `ns.Pin(frame, apply)` keeps a Blizzard frame where ForeverUI put it.
- The competitive bar (from a web survey on 2026-10-02): **EllesmereUI** (6.5M downloads, one build for Retail and Forever since Sep 20, 2026) is the suite players compare against on Forever; ElvUI 15 exists for 12.x with reduced features and had no Forever build in late September. Players' table stakes: a fast unlock/edit mode that coexists with Edit Mode, per-element scale/opacity, pixel-perfect borders, an installer with layout and resolution presets, profiles with per-spec switching and import/export strings, shared fonts/textures (LibSharedMedia), class colours plus an accent, mouseover/combat visibility conditions, action bars with keybind mode and cooldown text, a one-bag view with search/sort/junk sell, chat copy/URLs/short channels, a square minimap with a button collector, Blizzard window skins, a restyled quest tracker, searchable options, and no Lua error popups after patches. Differentiators: live-preview editor, per-content overrides, multi-condition visibility, Cooldown Manager and damage-meter skinning, bag categories, a skin/plugin API (Masque-compatible), Wago profile sharing, published CPU/memory numbers.
- **First in-game run (2026-10-02).** The owner loaded v0.3.0 in the Forever client (build 1.60.1) and sent screenshots: the addon loads and draws the HUD; the ForeverUI game-menu button is last in the menu (P0.9 moves it first); the bottom-right menu and bag strips overlap and look poor (P0.14). The "never run in game" caveat below still applies to everything else.
- **Blizzard's UI source for Forever** is mirrored at `https://github.com/Gethe/wow-ui-source`, branch `forever` (build 1.60.1.70170 on 2026-10-01). Forever loads files tagged `[AllowLoadGameType camelot]` and the `Camelot/` folders (`[Game]` in a TOC); use it to confirm a widget method or template before adding it to `scripts/lib/wow-widget-api.lua`. A shallow clone takes about a minute: `git clone --depth 1 --branch forever https://github.com/Gethe/wow-ui-source`.
- Forever beta findings reported by fan sites (unconfirmed, may change by launch): secure snippets failed to compile in build 1.60.1.69913 (would break state drivers, `SecureGroupHeader` `initialConfigFunction` and `SecureHandlerWrapScript`), `WOW_PROJECT_ID` reports 1, and the `GetItemInfo`/`GetSpellInfo` globals are gone. The code already prefers `C_Item`/`C_Spell` and uses the interface version; the snippet problem is P0.11.
