# Vanguard

> **Formerly ForeverUI.** Renamed in 0.4.0 because another, unrelated addon called ForeverUI is published on CurseForge and Wago, and two addons with the same folder name overwrite each other. The slash commands are now `/vg` and `/vanguard`. Settings don't carry over by themselves (the saved-settings file is named after the addon): before updating, type `/fui export` in game and keep the string; after updating, `/vg import` it (old ForeverUI strings import fine). Then delete the old `Interface/AddOns/ForeverUI` folder.

A from-scratch UI suite for WoW Forever (the 12.1 engine with vanilla content; the TOC declares Interface 16001 for Forever and 120007).
Written from scratch. It contains no code, art or fonts from other UI addons. It bundles three small shared libraries, unmodified, in `Libs/`: LibStub, CallbackHandler-1.0 and LibSharedMedia-3.0, which addons use to share fonts and bar textures (see Credits).

## What's in it

- **Look and layout**: the Slate & Brass theme: flat slate panels (floating windows get a soft shadow; frames on the HUD stay flat unless you turn on Soft shadows under frames), a brass accent (or arcane, fel, void, ember), bundled Fira Sans Condensed, pixel-perfect borders, smooth bars (Vanguard, Soft or Flat bar texture), shared fonts and bar textures (the Font and Bar texture pickers under General also list every font and bar texture other addons share through LibSharedMedia, and Vanguard shares its own font and bars the same way; if the addon behind your pick is gone, Fira Sans Condensed and the Vanguard bars come back), soft sparks on cast and power bars, quiet fades (never longer than 0.15 s in combat) and interface sounds (Reduce motion and Interface sounds switches turn them off; every fade and sound is listed in `docs/THEME.md`). Every frame can be moved in unlock mode (`/vg unlock`), with a grid, snapping and arrow-key nudging; right-click a frame's handle to set its anchor, exact offsets, scale (50% to 200%) and opacity (10% to 100%), or pick a frame under General → Layout and use its Scale and Opacity sliders. A scaled frame grows around its anchor point, which stays where it was; a frame that fades by itself (a mouseover bar, say) still fades, at its opacity. Scale and opacity are saved with the frame's position, go with the profile (export, import, switching), and `/vg reset` puts them back to 100%. The game's Edit Mode shows Vanguard's handles too, with a note under its window, so you can move everything in one place (a switch under General turns that off). Vanguard's frames replace the game's, so Edit Mode shows no handle for a game frame Vanguard has hidden (the game's action bars, XP and reputation bars, unit, boss and cast bar frames, the quest tracker while Vanguard's is on, and the rest); it keeps every system Vanguard doesn't replace. Profiles can be exported and imported, and can switch with your spec (on clients that have specializations). A whole-profile string also carries the UI scale and screen size it was made on: importing one asks whether to use its UI scale (the game's own UI scale setting, applied out of combat), then offers the reload. A profile remembers which of the game's Edit Mode layouts you use with it (that goes in its string too): when a character loads a different profile than last time (a switch, a spec profile or an import), Vanguard switches Edit Mode to that layout, out of combat, if your account has one of that name, and says so in chat; characters sharing a profile keep their own layouts. Choosing a profile (the list under `/vg` → Profiles, the picker at the top of the window, `/vg profile <name>`, an imported whole profile or a spec change) takes effect when you reload: until then the frames on screen still belong to the profile you were using, so moving a frame or changing the accent changes that one, and the Profiles page says which profile comes next (**Use** on the profile in use takes the switch back).
- **Centered layout**: everything near the action is anchored to the bottom center of the screen, so the layout keeps its shape at any UI scale. Player and target sit either side of your character with your cast bar and swing timer between them, the pet and target of target outside them, the focus above the player, and three bars of 38 px buttons under them over thin XP and reputation bars. Party and raid frames grow up from just above your player frame, centered on it (Setup's healing layout centers them above the middle of your frames), and a raid of more than 10 is drawn smaller (80%, or 72% above 25) so all 40 fit. Chat starts in a bottom-left spot under the frames, sized once; move it with `/vg unlock` (the game's own layout and your resizing are left alone after that), or switch the spot off under Bars, map, chat. A test checks that nothing overlaps or leaves the screen, solo to 40-man, at UI scale 1.0 and pixel-perfect, and with each of setup's screen presets on the screen it is made for. Frames you moved keep their spot; `/vg reset all` puts everything back.
- **Unit frames**: player, target, target of target, focus and party frames, and boss frames (up to five, in a column from the top-left corner, each shown while its boss is in the fight; the game's own boss frames are hidden). The player and target frames are 240 x 36 with 12 px names, sized for a 1080p screen at setup's 80% UI scale. On WoW Forever they show levels (colored by difficulty) and health as a percent, and a diamond marks elite, rare and boss targets. Combo points for rogues and druids above the player frame. Under it, shamans get their totems (icon and time left; right-click one to destroy it) and druids their mana while bear or cat form shows rage or energy: the game keeps both inside its own player frame, which Vanguard replaces.
- **Combat timers**: a swing timer with a row per hand (main hand, off hand, and ranged for a hunter's Auto Shot), from WoW Forever's own swing events. It is on for warriors, rogues and hunters, and can be set to always or never. While it is on, the game's own swing timer (its Show Swing Timer setting) is hidden; while it is off, the game's bars are drawn in the theme, each hand in its row's color. On your power bar, a spark counts down the five-second rule after each mana spell, or crosses the bar with every two-second energy tick.
- **Readouts**: your threat on your target as a percent above the target frame (in the threat colors once you have aggro), and a dot on the pet frame for a hunter pet's happiness: green happy, orange content, red unhappy. Each shows only where the client answers.
  - Target and focus auras: debuffs under the frame (a crowd-control slot, then yours soonest-first, then others' dimmed if you turn "Only your debuffs" off), the target's buffs above it, each row wrapping at the frame's width. Timer numbers are off by default (the dark sweep shows time left) and can be turned on.
  - Cast bars for you, your target and your focus, with a spark, the seconds left, your latency at the end of your own cast, and a gray edge on a cast you can't interrupt. The game's own cast bar over the professions window while you craft stays, in the theme's bar and font.
- **Your buffs and debuffs** replace the game's buff frame (and the external defensives and deadly debuff frames of newer clients, WoW Forever's among them): buffs in rows left of the minimap with timers, your debuffs on a new row under them (edged in their type's color); right-click a buff to cancel it. Weapon enchants (poisons, stones, oils, and a shaman's imbues on WoW Forever, which the game's own enchant cells miss) sit in front of the buffs. Move them with `/vg unlock`.
- **Raid frames** (built for healers):
  - Laid out in zones that never overlap: name at the top, status (missing health, Dead, Offline) under it, the missing-buff mark in the top-right corner, debuffs bottom left, your HoTs bottom right, the power bar along the bottom, and the ready check and resurrection big in the center. Default tile 100 x 48, drawn smaller in bigger raids. The missing-health text grows and shrinks with the tile but never drops under the theme's smallest text size on screen; on a grid drawn smaller (more than 10 players) it moves to the right end of the name row to keep that size.
  - Readable at a glance: class colors softened into the panel color by default, with a 1-pixel line in the full class color along each tile's top so close colors (shaman and mage blues, rogue and paladin yellows) still tell apart (or dark bars with class-colored names, or bright class colors), outlined names that end in "..." when too long, and a dark bar on the dead and offline. In instanced combat, where the game keeps health secret from addons, the bars still fill and the missing-health text hides.
  - Auras: the first debuff you can dispel, then up to two others (boss debuffs included); your HoTs, lit while they're in their refresh window; no timer numbers on these small icons. A debuff you can dispel washes the tile in its type's color from the bottom and colors its edge.
  - Healing: click casting and hover keybindings (a hover key can carry Shift, Ctrl or Alt: while the pointer is over a frame, Shift-Q casts on that player), incoming heals and shields, aggro strip, missing-buff marker (hidden while the game hides auras, so it never cries wolf), an accent edge on your target, a faint wash under the mouse.
  - Status: range fade, raid target icons, ready check (a check, cross or three dots in the theme colors), resurrection marker, and a gold crown for the leader and a small diamond for assistants. While the ready check or resurrection mark shows in the middle, the missing-health text steps aside.
  - Roles: a small shield for tanks and a cross for healers before the name; damage dealers get no mark. The raid's main tank gets the shield in your accent color, and the main assist in gray.
  - Groups as columns (the default) or rows: columns put each group's five players in a column, with the groups side by side; rows put each group's five in one row, with the groups stacked upward, so a big healing raid is wide and short. Pick it with **Groups as** on the Raid frames page in `/vg`; a change takes a reload.
- **Click casting** (`/vg` → Click casting), set up without typing a spell:
  - **Starter layout**: one button fills the grid with your class's healing layout (Priest, Druid, Paladin, Shaman; Mage and Warlock get their buffs). Spells bind by name, so one you haven't learned yet starts working the day you learn it. Left click stays Target and middle click the unit menu.
  - **The grid**: mouse buttons down the side, Plain / Shift / Ctrl / Alt across the top (More modifiers adds the combinations); each cell shows the bound spell's icon. Click a cell to pick from your own spellbook, right-click to clear it, or drop a spell from the spellbook or a bar onto it.
  - **The picker** lists what you can cast on friends in groups (Heals, Protect & cleanse, Buffs, Other), with a search box and the spell's tooltip on hover. A spell with ranks binds as its highest rank unless you open its ranks and pick one (for downranking); then the cell says "Flash Heal (Rank 3)". Under the spells: Target, Unit menu, Focus, Assist, a macro, or a typed spell name.
  - **Hover keys**: Add key, press the key (Shift + Q, the wheel...), pick the spell; the row says when the key is also an action-bar binding ("also Action bar 1 slot 2"), which it keeps doing off the frames.
  - **Try it**: hover the sample tile and press or click; it says what would happen ("Shift + Right click -> Renew on you") without casting.
  - **Share**: Export and Import the bindings as a string, and copy them to another spec where the client has specs. Bindings are per character and spec; changes apply at once, or when the fight ends if you're in one.
  - **The game's click bindings** (where the client has its own click casting): a switch at the bottom of the page, off by default, uses the game's instead. Vanguard's bindings and hover keys then rest (kept for when you switch back, and `/vg binds` says so), and the bindings you set in the game's Click Casting window (the page's button opens it) work on the raid and unit frames. The switch applies out of combat; turned on in a fight, it waits for the fight to end.
- **Raid tools**: for the group's leader and assistants, a small bar at the top left with a ready check, a 10-second pull timer (right-click cancels it), a role check and Raid (turns your party into a raid), the eight raid target icons (click to mark your target; the last button clears it) and the eight world markers (click to place or remove one; right-click clears it; the last button clears them all). It shows and hides out of combat.
- **Action bars**: range and power tint, plus restyled pet, stance and extra action buttons and a vehicle exit button. The restyle keeps what the game lights up by state: the active stance, the pet's attack flash and the auto-cast mark. The possess bar's two buttons, shown while you mind-control, get the same restyle. The pet and stance bars sit in spots of their own at the bottom left, above the chat and clear of your bars (the game's own spot for them lies over the bar stack); move them with `/vg unlock`, or turn that off under Action bars to leave them to Edit Mode.
  - The bottom bars stack with bar 1 on top; turning on another bottom bar adds it underneath. Each row takes its bar's real height, so a bar with bigger buttons or more rows pushes the ones above it up, right away when you change it. A position you've dragged is kept; `/vg reset all` puts the bars back in this order.
  - Empty slots stay hidden until you drag a spell or item, so a new character sees no empty squares, and they take no mouse, so clicks and right-drag camera turns over blank bar space reach the game. A slot that fills or empties in combat (bar 1 paging into a form) shows or hides at once, but takes or releases the mouse only when combat ends; its key still works.
  - Hover a button for its action's tooltip, in the game's default spot; it follows the page bar 1 is on, and an empty slot shows none.
  - The game's self-cast, focus-cast and mouseover-cast options work on these buttons as on the game's own.
  - Keybind mode (`/vg keybind`, or **Keybind mode** under Action bars): hover a button and press a key, the middle or a side mouse button, or roll the wheel (with Shift, Ctrl or Alt held if you like) to bind it; the key replaces the button's keys, is saved in the game's own key bindings (for your account or this character, whichever you use), and shows on the button at once. A tooltip over the button shows its keys. Backspace or Delete clears them. A key that did something else (Move Forward, another button) is taken, and chat says from what. While the mode is on a click binds instead of casting (left and right click bind nothing, as in the game). A modifier pressed alone does nothing, a key pressed away from the buttons goes on to the game, and Escape leaves. Empty slots and faded bars show while it is on. It works out of combat only and ends when a fight starts.
  - Counts, icons and usability follow what you carry and wear (bags, equipment), your form, macro edits and spell charges, so a stack you use up or a form that changes an icon updates at once.
  - Each bar has its own number of buttons, buttons per row, button size, and visibility: Always, On mouseover (seen only while the mouse is over it), In combat, Hidden, or When checked below: a row of conditions under it (Combat, Mouseover, Group, Raid, Instance, Vehicle, Resting), and the bar shows while any checked one holds (with Mouseover checked it fades in under the mouse the rest of the time). The game itself shows and hides the bar on those conditions, in combat too; In an instance is re-checked whenever you change zone (after a fight, if you are in one). While you drag a spell or item, bars on mouseover or on conditions show too (the latter only when the drag starts out of combat).
  - Hidden bars keep their keys: the bar isn't drawn, but a bound key still casts, like a keybind-only bar. A Hidden bottom bar keeps its row in the stack (leaving a gap), because bars can't be re-stacked during combat.
  - The right-edge bars (4 and 5) start off; turned on, they show on mouseover. Profiles that already had them on keep them on Always.
  - With the Masque addon installed, Masque skins the buttons instead of Vanguard: its options list four Vanguard groups (Action bars; Pet, stance and extra buttons; Buffs and debuffs, with the weapon enchants; Target and focus auras), each with its own skin. Vanguard bundles nothing of Masque; without it nothing changes.
- **Nameplates**: class/reaction/threat colors, the name in outlined text with the level (colored by how hard the unit is for you), your debuffs (soonest to expire first, with timers) and your crowd control, casts, raid icon, an accent border, a 2-pixel accent glow and a diamond on your target, and a gold "!" by the name of units your quests need (only when the game says so plainly; a switch turns it off). Players' plates show their buffs right of the bar: big and external defensives and important buffs (immunities, major cooldowns) on friend and foe, and the buffs you cast on friendly players (3 a row by default; none, 3 or 5). A click lands on the plate as Vanguard draws it, the name and bar plus a little around them, and the client stacks plates by that same box; friendly players' plates stay clickable even with the game's name-only option for them on. The plate under the mouse gets a faint wash, so you can see which one a click will hit. A plate first drawn during a fight uses Vanguard's own icons (the client's aura containers can't be made in combat) and switches to the client's when the fight ends.
- **Text size**: one slider (/vg > General, 70% to 130%) sizes all of Vanguard's text, chat and tooltips included, and applies at once. Chat has its own Small, Medium or Large on top (or keeps the game's own chat size if you prefer). `/vg status` shows your UI scale and how many pixels tall chat text draws on your screen.
- **The game's extras, tidied**: the game's own XP bar is hidden while Vanguard's shows (no more double XP bar), and so are the durability figure, clock and calendar button while the info strip shows them (`/calendar` still opens the calendar). Tracking, mail, dungeon difficulty, the addon compartment and the group finder eye move onto the square minimap's corners (tracking and the addon compartment as slot buttons like the menu bar's, with Vanguard's icons, on the band along the map's bottom), and the expansion button (nothing to show in vanilla content) is put away; the game's emptied minimap frame at the top right stops taking mouse clicks and its zone button is put away. The bag buttons and the micro menu share one bar in the bottom-right corner: the bags (the key ring too, where the client has one, on the same slot as a bag) in a row centered over the menu buttons, with a thin accent line between them under the slots. The bar hugs its slots with a 12-pixel margin all round and grows to the left from its bottom-right corner as the game adds buttons. Every button sits on a slot 24 pixels wide with a 4-pixel gap (a slate tile with a beveled edge and a small soft shadow; the menu row's slots are 30 tall, the game's menu plates' own shape, so each plate fits its slot whole) and keeps the game's own icon and alert flash, fitted inside the slot; an inner edge in your accent shows under the mouse and darkens while you press, and a disabled menu button turns grey. Each bag's slot has a thin bar along its bottom showing how full that bag is (red when it is full; a soul bag or quiver counts only its own slots), an empty bag slot shows the game's empty-slot art faint and grey, and the backpack shows how many slots your bags have free. Vanguard's line icons stand in for the game's menu icons (on by default; the switch under Bars, map, chat brings the game's own back, and a profile saved before the bar was reworked keeps the game's icons until you switch). The bar is always shown; you can choose On mouseover, Auto-hide after 10 s (shown when you log in and while the mouse is over it, faded 10 seconds after the mouse leaves), In combat, Hidden or the same row of conditions as the action bars instead, under Bars, map, chat; it applies at once. The game's own bar frames are hidden inside it, and a spot you gave the menu strip is kept (a separate bag strip's spot is dropped, since the bags now ride in the bar). The quest tracker has its spot under the info strip: Vanguard's own tracker fills it, and only with that switched off does the game's tracker sit there instead, with flat headers, a brass line under each, the theme's collapse arrows and the theme font (quest colors stay the game's). The bar sizes itself to its buttons, re-fits whenever the game lays the bars out again, and stays where it's put when the game lays out its own frames. Each has a switch under Bars, map, chat.
- **Game windows**: the game's own windows keep their layout and buttons and get Vanguard's flat panel, close button, title and buttons. Each group below has its own switch under Bars, map, chat (a reload applies it).
  - Character, merchant, mail, quest and gossip (only when Vanguard's quest dialog is switched off), trade, loot and roll windows, the game menu, the ready check, popups, the spellbook and the breath and fatigue bars get a flat Vanguard panel reaching a little past the window so its contents have room, close button (and the maximize and minimize buttons, with Vanguard's glyphs; the close button turns red under the mouse), title and buttons; tabs sit just outside the panel, the selected one raised with a brass bar on its outer edge and the others' icons greyed (the mail's Open All too; the game menu's buttons are made again each time it opens and are re-dressed each time, its header plate is hidden, and the Vanguard button on it matches). Friends, the dressing room, the flight map, books and letters (their pages in light text on the dark panel), and the windows that load later (auction house, professions, inspect, guild bank, collections, achievements, dungeon journal) get the same look. Loss of control (stunned, feared...) shows on a flat panel a little above your character, and the talking head on one at the top center (or hidden; your choice under Bars, map, chat). On a Hardcore realm, the game's death notices (the red lines at the top center) take the theme font and the theme's red. If you like (off until you switch it on, under Bars, map, chat), a rare that shows up on your minimap is announced with the raid warning sound and one chat line, out of combat and once per rare. The character pane shows each worn item's durability on its slot, colored like the info strip's. Their own layout and buttons stay as the game has them. Switches under Bars, map, chat.

Switch: "Game options, Edit Mode, keybinding and help windows" under Bars, map, chat (a reload applies it).

The info strip can show this session's sales (Bars, map, chat → Strip under the minimap).
- **Crafting costs**: with a recipe open in the profession window, a Vanguard panel to its right says what the recipe costs and earns at the auction house: each reagent with how many and what they cost (at its market value from your scans and searches on this realm and faction, else its cheapest price; "no price" when none was seen), what the reagents come to ("at least" while one has no price), what the crafted item sells for (times the average number made; an enchant makes nothing to sell) and the profit, in green, or in red for a loss, before the auction house's cut (shown only once every price is known). Type how many crafts beside **Add reagents** and click it: each reagent joins your Keep-stocked list (`/vg stock`) with what that many crafts need (a larger count you already keep stays), so a merchant who sells it tops you up, and the Restock shopping list is made of what you're short of (searched at once at the auction house). Optional and finishing reagents are left out. A switch under Bars, map, chat (Auction house) turns the panel off.
- **Auction prices for other addons**: `Vanguard.API.v1` gives other addons this realm and faction's auction prices, vendor prices and disenchant values, tells them when new prices come in, makes and changes shopping lists, and searches the auction house through the Shop card (one search at a time, only while it is open), with the same function names as Auctionator's API so an addon written for it can switch easily. It never posts, buys or cancels. Addon authors: see [docs/API.md](docs/API.md).
- **Options**: `/vg`, the addons button, or the **Vanguard** button at the top of the game menu (Escape). When Vanguard has caught errors this session, the addons button carries a small red count and the options window's footer says how many (click that line to list them in chat, as `/vg errors` does); with none, or after `/vg errors clear`, there is no badge. Turn any module off under Modules to keep the default one. A setting changed from its default gets a small accent dot by its caption (click it to put the default back), and a page holding any such setting gets one in the list on the left. With the window open, Up and Down go through the pages and Tab (Shift-Tab back) through a page's settings, Enter or Space pressing the one marked; other keys still reach the game, and nothing is taken while you type in the search or a box, or in a fight. The top of General shows a unit frame and an action button in your accent, font, text size and bar texture as you change them. Most changes apply at once; the rest show a Reload now button. WoW Forever lets an addon reload only from a click on a secure button, so that's what Vanguard's Reload buttons are; one built during a fight becomes one when the fight ends, and until then it asks you to type `/reload`.
- **First-run setup**: the first time you log in on an account, a four-step wizard asks for a layout (Damage and tanking, Healing, Like the game's, or Keep my current layout, which moves nothing; a healer, by specialization or else by group role, starts on Healing, anyone else on Damage and tanking), sizes for your screen, an accent (color swatches) and a raid frame style (three small raid tiles, each drawn in its style in your class color), then unlocks your frames so you can move them (the same unlock mode as `/vg unlock`, or **Move frames** under General in `/vg`; `/vg lock` or Done locks them again). With the defaults it takes four clicks: Next, Next, Next, Done. The screen step offers 1080p, 1440p, 4K and ultrawide presets and picks the one for your screen (or Keep my current sizes, picked on a screen under 1000 pixels tall): each sets the game's UI scale (1080p 80%, 1440p and ultrawide 70%, 4K 65%, the bottom of the game's own range; it sizes the unit frames, which every layout draws in UI units), the action button size (38 px, the default), the raid tile size (100 x 48, or 110 x 48 on the bigger screens; it shows after a reload, which setup offers) and the text size (100% to 110%). The UI scale is the same setting as the game's Options → Graphics → UI Scale, applied out of combat; a preset turns Vanguard's pixel-perfect scale off, since that would replace it. It waits until you're out of combat. Done finishes it, and so does **Skip setup** on its first step (which applies nothing); the close button and Escape only close it, and it opens again at your next login until it's finished. Each new character on an account that has finished setup gets it too, with a Profile step first: share the profile your other characters use (changes there change them too), or give this character a profile of its own, named after it, that starts as a copy of that one, with no reload; a profile of its own then starts on your role's layout, and Back doesn't return to the Profile step. Characters that played before this came in aren't asked. To run it again: `/vg setup`, or **Run setup** under General → Layout in `/vg`; run again (or on a new character sharing a profile), it starts on Keep my current layout and Keep my current sizes, so clicking through changes only what you pick. **Start over** on the Profiles page resets the profile and opens setup after the reload, starting on your role's layout and your screen's sizes. Damage and tanking is Vanguard's defaults (picking it puts back anything another layout moved); Like the game's puts your player and target frames along the top left as the game has them (the pet under the player, the target of target and focus beside the target), the party and raid down the left side, the boss frames on the right under your buffs, and the raid tools and main tanks near the top center; Healing turns click casting on and centers the party and raid frames on the screen above the cluster around your character: their bottom edge sits 4 units above the top of the focus cast bar's default spot (the top of the cluster), and the grid grows upward from there, so it doesn't cover your frames. Healing doesn't change how the groups are laid out; that's **Groups as** on the Raid frames page in `/vg` (Columns, the default, or Rows; a change takes a reload). A test checks all three layouts with groups as columns and as rows, solo and with 5, 25 and 40 players (raids above 10 are drawn smaller), on a 1365 x 768 screen at UI scale 1, on 1920 x 1080 pixel-perfect, and with each screen preset on the screen it's made for: with Vanguard's default spots nothing overlaps and nothing leaves the screen. To put the raid frames somewhere else, drag them with `/vg unlock` (or **Move frames** under General in `/vg`).

Every client call is checked before use, and values the client hides from
addons go to the bars unread. Auras use the client's own aura containers where
it has them (12.1 and WoW Forever), so icons, stacks, timers and debuff colors
keep working while it hides aura values in instanced combat; if the client
refuses one of those containers, Vanguard switches to its own icons for the
rest of the session (it says so in `/vg errors`); on those icons, an aura
filter word the client doesn't know (say crowd control) is dropped for the

If the client can't compile secure snippets (a WoW Forever beta bug), Vanguard says so at login and in `/vg status` and turns hover keys off; mouse click-casting still works, bar 1 still pages with stances, forms and Shift+number (through the game's own page attribute rather than a snippet), and the raid and main tank tiles are set up without one. Download `Vanguard-<version>.zip` from the [latest release](https://github.com/clifftaylor2325/wow-vanguard-ui/releases/latest) and unzip the `Vanguard` folder into `World of Warcraft/_retail_/Interface/AddOns/` (your Forever client's AddOns folder).

## Skin API (for other addons)

```
## OptionalDeps: Vanguard
```
```lua
if Vanguard and Vanguard.RegisterSkin then
  Vanguard.RegisterSkin("MyAddon", function(S)
    S.Panel(MyFrame, { shadow = true }) -- flat panel, 1px border, sheen; shadow for floating windows
    S.Button(MyFrame.OkButton)
    S.EditBox(MyFrame.Input)
    S.CloseButton(MyFrame.Close)
    S.Text(MyFrame.Title, "title")  -- text roles: title, heading, name, cell, label, number, small, tiny, world
    S.Color(MyFrame.Hint, "text2")  -- theme colors by name: text, text2, muted, accent, good, bad...
    S.Tint(MyFrame.Glow, "accent")
  end)
end
```

The callback runs once at login, or immediately if the addon registers after login. Errors in it are reported and don't break anything else. Painted frames follow `/vg accent` changes live, and their borders stay one screen pixel at any UI scale (`S.Pixel(frame)` gives that size). `S.RGB(name)` returns any theme color; the names, text roles and the rest of the look are listed in `docs/THEME.md` (from `Core/Theme.lua`). `S.apiVersion` is 1; the API only grows.

## Development

```bash
npm install
npm test          # JS and Lua harness tests under Vitest, once (vitest run, no watch), then a per-area Lua harness summary
npm run test:quick # the JS tests and the Lua smoke tests (both clients, and secret geometry): what a pull request's check runs
npm run verify    # npm test (real addon Lua in a TEST-ONLY headless WoW client, and the JS tests), then the code-quality scan
                  # (functions of 10 lines or fewer, all documented; colors only from Core/Theme.lua)
npm run coverage  # every test with line coverage of the addon Lua; fails below scripts/lua-coverage-floor.json (100%)
                  # run it before you open a pull request: CI runs it when a pull request is opened ready or marked ready for
                  # review (not a draft), on later pushes only while it carries the full-tests label, weekly, before each
                  # release and from the Actions tab, not on every push (a private repository's Actions minutes count)
npm run lint      # luacheck
npm run timing    # the suite on 2 workers (the hosted runner's size): wall time, per-file table; --budget and --baseline fail it
npm run profile -- <area>  # where the Lua of one test area (or "login") spends its time, by file, function and line
npm run media     # regenerate Media/Textures and Media/Icons from scripts/lib/media-sources.mjs
npm run package   # dist/Vanguard-<version>.zip from committed files
npm run preview   # preview/*.png: the default layout and the options window (needs Playwright)
```

**Play from your clone:** `npm run link:wow -- --wow "<Forever folder that has Interface/AddOns>"` links `Interface/AddOns/Vanguard` to this clone (a directory junction on Windows, no admin needed), so an edit plus `/reload` shows in game. The folder is remembered in `~/.wow-forever/config.json`, so after the first time it's just `npm run link:wow`. An installed copy is only moved aside with `--replace` (it becomes `Vanguard.backup-<date>`). `--status` shows what's there; `--unlink` removes the link and never deletes a real folder.

`docs/SMOKE-TEST.md` is the in-game checklist to run after a release lands: what to do, what to expect and what to paste back for each step.

**VS Code:** open the folder and accept the recommended extensions: **Lua** (sumneko) and **WoW API** (Ketho), which add Lua 5.1 checking plus autocomplete and docs for the game API. `.vscode/tasks.json` has verify, luacheck (problems show in the editor), coverage, package, preview and link:wow under *Run Task*.

**Windows tools:** `npm run verify` needs only Node. For `npm run lint`, put `luacheck.exe` from the [luacheck releases](https://github.com/lunarmodules/luacheck/releases) on your PATH. CI also runs a Lua 5.1 syntax check (`luac5.1 -p`); you don't need it locally.

**Release:** bump `## Version` in `Vanguard.toc` and merge, then run the `release` workflow from the Actions tab on `main` (it tags `v<version>`), or push a matching tag. It runs the whole suite with the coverage floor first, then publishes a GitHub release with the zip.

**Art and fonts:** every texture and icon under `Media/` is made by code in `scripts/lib/media-sources.mjs`: most drawn in plain math (no image editor), the options nav's and minimap's icons and the faction crests rasterized from game-icons.net SVGs in `art/game-icons` (credited in `art/CREDITS.md`); `npm run verify` fails if a committed file doesn't match its source. The fonts are made from upstream Fira Sans Condensed by `scripts/fonts/make-fonts.py` (see that file).

**Testing the addon:** `scripts/tests/<area>.test.mjs` play the addon's real Lua in a headless client built for the tests (`scripts/lib/wow-*.lua`): Lua 5.1 semantics, frames with real layout on a 1920x1080 screen, a world model (units, auras, actions, quests, combat, timers) behind the game API, and mouse and keyboard input. A test sets up the world, acts as the player would, and asserts on what the addon drew. The client also holds the addon to the game's taint rules: a test fails if the addon stores a field on one of the game's frames or touches a protected frame in combat, and it can hide positions and sizes as secrets the way the client does in a fight. The guide is [scripts/tests/README.md](scripts/tests/README.md).

**Code quality:** every function has a comment on the line above it and at most 10 lines of body code; `npm run verify` and CI enforce it on every pull request. The shared libraries in `Libs/` stay exactly as upstream wrote them, so the scan, luacheck and the coverage count leave them out.

**CI:** every pull request gets `verify.yml` ("Quick checks": the code-quality scan, luacheck, Lua 5.1 syntax, `npm run test:quick` and the release zip, inside a minute), and `main` requires it to merge. The whole suite with the coverage floor and the UI preview (`lua-suite.yml`) runs when a pull request is opened ready for review or marked ready for review (a draft doesn't run it), on every later push while the pull request carries the `full-tests` label, weekly (shuffled), before each release and from the Actions tab (*full suite* → *Run workflow*). A later push without the label stops a full-suite run still in progress for that pull request (the code it was testing is stale), and adding any other label neither starts nor stops a run. A red weekly run opens an issue labelled `ci-failure`, which the next green run closes. Run `npm run coverage` yourself before opening a pull request, since CI doesn't run it on every push: a private repository's Actions minutes are counted, and the gate is kept to one billed minute. Code scanning (GitHub Advanced Security's default setup) stops once the repository is private; nothing here depends on it.

### Releases on CurseForge

`.pkgmeta` tells CurseForge's packager (and Wago's, and the BigWigs packager) what goes in the `Vanguard` folder: exactly what `npm run package` puts in the release zip. `scripts/pkgmeta.test.mjs` fails if the two ever differ, so add a new top-level file or folder to `.pkgmeta`'s ignore list unless players need it.

To publish there once the CurseForge project exists:

1. Add `## X-Curse-Project-ID: <id>` to `Vanguard.toc` (the number in the About box on the project's page), so the CurseForge app can match installed copies to the project.
2. Upload each release's `Vanguard-<version>.zip` to the project, or point CurseForge's packager at this repository and let it build from the release tag with `.pkgmeta`.
3. Set `CURSEFORGE_URL` in the website's `scripts/lib/html.mjs` to the project's page: its "Coming soon on CurseForge" badges become links.
